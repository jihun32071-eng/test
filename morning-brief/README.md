# 아침 브리핑

`아침브리핑구성안.md`(2026-09-09)를 앱으로 옮긴 것. 구성안 1번 표의 6개 항목이
카드 6개로 그대로 대응합니다. 프레임워크도 번들러도 없고, `index.html` 하나가
앱 전체입니다. 나머지 파일은 홈 화면에 설치하고 오프라인에서 열기 위한 껍데기입니다.

```bash
sh 실행.sh                       # → http://localhost:8000
```

`file://` 로 열어도 화면은 뜨지만 서비스워커(오프라인·설치)는 http(s)에서만 붙습니다.
그래서 더블클릭 대신 작은 서버를 띄웁니다.

## 휴대폰에 앱으로 넣기

### 안드로이드 — APK (설정 건드릴 것 없음)

`app/` 아래 Capacitor 껍데기가 있고, `app/**` 이나 `morning-brief/index.html` 이
바뀌면 CI 가 APK 를 빌드해 릴리스에 올립니다. 폰 브라우저로 열어서 받으면 됩니다.

    https://github.com/jihun32071-eng/test/releases/tag/morning-brief

서명 없는 디버그 빌드라, 설치할 때 폰 설정에서 "출처를 알 수 없는 앱 설치"를
한 번 허용해야 합니다. 플레이스토어 앱과는 별개로 설치됩니다.

APK 안에서는 PWA 조각(manifest·설치 버튼·서비스워커)이 걷힙니다 — `sync-web.mjs`
설명 참고.

### 사이트에서 받기 — `install.html`

Pages 에 올라가면 설치 페이지가 생깁니다. 앱으로 설치(PWA)와 APK 내려받기를
한 화면에 놓고, 열린 기기에 맞는 것만 보여줍니다.

    https://jihun32071-eng.github.io/test/morning-brief/install.html   ← 설치
    https://jihun32071-eng.github.io/test/morning-brief/               ← 브리핑

기기 판별은 `beforeinstallprompt` 지원 여부와 UA 로 합니다 — iOS 는 설치 버튼을
띄울 방법이 없어 수동 절차를 보여주고, 안드로이드가 아니면 APK 카드에 그렇게
적습니다. APK 링크는 릴리스 고정 주소라 새 빌드가 올라가도 그대로입니다.

### 주소가 생기려면

홈 화면 설치는 **https 주소**가 있어야 됩니다. 이 저장소는 GitHub Pages 가 이미
켜져 있고 **기본 브랜치 루트**를 서비스하므로, `morning-brief/` 가 기본 브랜치에
들어가면 바로 위 주소가 생깁니다. 병합 외에 따로 할 설정은 없습니다.

> Actions 로 배포하는 워크플로를 두는 방법도 있지만, `github-pages` 환경은
> 기본적으로 **기본 브랜치에서만** 배포를 허용합니다. 기능 브랜치에서 돌리면
> 로그도 남기지 못하고 몇 초 만에 실패합니다 — 그래서 그 워크플로는 뺐습니다.

- **iOS 사파리** — 공유 → 홈 화면에 추가 (`beforeinstallprompt` 가 없어 버튼은 안 뜹니다)
- **데스크톱·안드로이드 크롬** — 주소창의 설치 아이콘, 또는 앱 헤더의 "설치" 버튼

설치하면 주소창 없이 뜨고, 비행기 모드에서도 열립니다. 기록은 그 기기의
`localStorage` 에 남습니다. 저장소 루트의 `.nojekyll` 은 Pages 가 파일을 Jekyll 로
가공하지 않고 그대로 내보내게 합니다.

## 파일

| 파일 | 역할 |
|---|---|
| `index.html` | 앱 전부 — 마크업·스타일·로직. **여기만 고치면 됩니다** |
| `app.webmanifest` | 앱 이름·아이콘·시작 주소. 홈 화면 설치에 필요 |
| `sw.js` | 오프라인 캐시. 내용을 바꾸면 안의 `VERSION` 을 올리세요 |
| `icon.svg` / `icon-*.png` | 아이콘. PNG는 `icon.svg` 에서 뽑은 것이라 SVG가 원본입니다 |
| `build-artifact.mjs` | 아티팩트 게시용 본문 생성 (`dist/artifact.html`) |
| `strip-pwa.mjs` | PWA 조각 걷어내는 규칙. 아티팩트 빌드와 APK 빌드가 공유 |
| `make-android-icons.sh` | `icon.svg` → 안드로이드 런처 아이콘 (`app/android-res/`) |
| `install.html` | 사이트에서 설치·APK 받는 페이지 (Pages 전용, 앱에는 안 들어감) |
| `실행.sh` | 로컬 서버 띄우고 브라우저 열기 |

APK 껍데기는 저장소 루트의 `app/` 에 따로 있습니다 (`app/android-res/README.md` 참고).

## 어떻게 도는가

`<script>` 안이 전부이고 순서는 데이터 → 날짜 유틸 → 상태 → 저장 → 렌더 함수 →
테마 → 부팅입니다.

카드 머리의 작은 글씨는 구성안 표의 "판단 기준" 열을 그대로 가져온 것입니다 —
읽고 나서 뭘 정해야 하는지가 카드 제목보다 먼저 보이게 한 장치라서, 항목을
추가할 때도 이 질문부터 정하는 게 좋습니다.

| 카드 | 판단 기준 | 상태 |
|---|---|---|
| 오늘 일정 | 지금 나가야 하나? | 시각 입력 → 남은 시간 자동 계산 |
| 오늘 챙길 것 | 뭘 챙기나? | 칩 토글 (날씨는 기상청 링크) |
| 할 일 3가지 | 오늘 뭘 끝내나? | 3칸 고정 · 어제 미완료분 이월 |
| 덕질 일정 | 오늘 밤 뭘 보나? | 일정 데이터에서 자동 계산 |
| 어제 기록 | 오늘 페이스 조절 | 수면·운동·컨디션 + 7일 추이 |
| 오늘의 의도 | — | 날짜별 기본 문구, 수정 가능 |

## 손볼 곳

### 일정 갱신

파일 상단 `LIGA` / `UCL` / `KBO` / `LCK` 배열. 이게 유일한 데이터 소스입니다.

```js
{d:"2026-09-13", t:"04:00", opp:"라요 바예카노", ha:"홈", tag:"마드리드 더비"}
```

- `d` 없으면 D-day 계산에서 빠지고 표에만 `span` 문구로 남습니다 (KBO 미확정 경기용)
- `t` 없으면 "시간 미정"
- `tag` 붙이면 표에서 강조됩니다

시즌이 넘어가면 이 네 배열만 갈아끼우면 됩니다.

### 새벽 경기 처리 — `watchNight()`

이 앱에서 제일 신경 쓴 부분입니다. 04:00 경기는 달력상 내일이지만 실제로는
**오늘 밤에 보는** 경기라서, D-day를 하루 당겨서 계산합니다.

```js
function watchNight(m){
  var dt = parseD(m.d);
  if(isDawn(m.t)) dt = addDays(dt,-1);   // 06시 이전 = 전날 밤
  return dt;
}
```

그래서 9/9 기준 9/13 04:00 경기는 D-4가 아니라 **D-3**이고, 하루 전이 되면
"D-1"이 아니라 **"오늘 밤"** 으로 뜹니다. 경계값은 `isDawn()`의 06시.

### 하루가 바뀔 때 — `rollover()`

브리핑은 켜두는 화면이라 자정을 넘기는 일이 잦습니다. 시계 틱마다 날짜를
비교해서, 바뀌었으면 어제 것을 확정 저장(`flushSave`)하고 새 날짜 상태로
갈아끼운 뒤 다시 그립니다. 이게 없으면 첫 일정 카운트다운이 어제 날짜로
계산돼 계속 "지남"에 머뭅니다.

새 날의 첫 방문에는 `carryOver()` 가 어제 **못 끝낸** 할 일만 넘겨받습니다.
끝낸 일·챙길 것·기록은 그날의 것이라 넘기지 않습니다.

### 저장

기본은 `localStorage`, 키는 `morningBrief:days/<YYYY-MM-DD>` 와
`morningBrief:checklist`, `morningBrief:theme`. 날짜별로 문서 하나라서 지난
기록이 그대로 쌓이고, 수면 스파크라인이 여기서 최근 7일을 읽습니다.

쓰기는 `scheduleSave()`(700ms 디바운스) → `persist()` 한 곳만 거치므로 백엔드를
붙이려면 `persist()` 만 바꾸면 됩니다. 탭을 숨기거나 자정을 넘길 때는
`flushSave()` 가 대기 중인 저장을 먼저 흘려보냅니다.

아티팩트로 게시하면 `claude.use("db")` 가 붙어 같은 내용을 서버에도 써서 기기
간에 이어집니다(`connect()`). 로컬에서는 이 경로가 조용히 건너뛰어집니다.

### 테마

`:root` 에 라이트 토큰 전체, `@media (prefers-color-scheme: dark)` 와
`[data-theme="dark"]` 에서 **토큰만** 재정의합니다. 색을 새로 쓸 일이 있으면
반드시 `:root` 에 먼저 선언하세요 — 미디어 쿼리 안에만 있는 색은 한쪽 테마에서
사라집니다.

헤더 오른쪽 버튼이 자동 → 밝게 → 어둡게를 돌립니다. 선택은 `localStorage` 에
남고, 깜빡임을 막으려고 `<body>` 첫 줄의 짧은 인라인 스크립트가 렌더 전에
`data-theme` 을 먼저 붙입니다.

### 서비스워커 (PWA 쪽만 해당)

`app.webmanifest` + `sw.js` 로 홈 화면 설치와 오프라인 실행이 됩니다. 등록은
`index.html` 맨 아래 `<!--pwa:-->` 블록에서 하고, **https 또는 localhost 에서만**
붙습니다 — `file://` 로 열면 등록되지 않습니다.

캐시 전략은 stale-while-revalidate — 아침에 열자마자 떠야 하는 화면이라 캐시를
먼저 주고 새 버전은 뒤에서 받아 **다음 실행**에 반영합니다. 그래서 고친 내용이
바로 안 보이면 한 번 더 열어보세요. `sw.js` 의 `VERSION` 을 올리면 옛 캐시가
정리됩니다.

APK 안에서는 이 블록이 통째로 걷힙니다. 자산이 이미 기기에 들어 있어 캐시가
필요 없고, 앱을 업데이트해도 서비스워커 캐시가 남아 지난 화면을 계속 내주기
때문입니다.

### 아이콘 다시 뽑기

`icon.svg` 가 원본입니다. 고친 뒤 안드로이드 런처 아이콘까지 다시 뽑으려면:

```bash
sh make-android-icons.sh          # → app/android-res/mipmap-*/
```

웹 아이콘(`icon-192.png` 등)은 헤드리스 크로뮴으로 직접 찍습니다. 툴바 높이 때문에
일반 `chrome --headless` 는 아래가 잘리니 **`headless_shell`** 을 쓰세요 — 이걸로
한참 헤맸습니다.

```bash
headless_shell --no-sandbox --hide-scrollbars --force-device-scale-factor=1 \
  --default-background-color=00000000 --window-size=512,512 \
  --screenshot=icon-512.png file://$PWD/icon.svg
```

### 아티팩트로 게시

```bash
node build-artifact.mjs      # → dist/artifact.html
```

아티팩트는 플랫폼이 `doctype`/`html`/`head`/`body` 를 직접 감싸므로 `<title>` +
폰트 링크 + `<style>` + 본문만 남기고, PWA 조각(`<!--pwa:-->`, `/*pwa:*/` 마커
사이)은 걷어냅니다. `dist/` 는 생성물이라 커밋하지 않습니다 — 소스는 언제나
`index.html` 하나입니다.

## 안 되는 것

- **날씨 자동 조회** — 외부 API 호출 없음. 기상청 링크 + 챙길 것 칩으로 대체
- **경기 결과 자동 갱신** — 레알 9/9 인터 밀란 2-1 승만 초기값(그것도 9/9에만).
  나머지는 팀 줄 "어제" 칸에 직접 입력
- **아침 알림** — 브라우저는 열려 있지 않은 앱을 정해진 시각에 깨우지 못합니다.
  푸시 서버를 두거나, 휴대폰 알람에 앱을 걸어두는 쪽이 현실적입니다
- **APK 안에서 웹폰트** — Gowun Batang·IBM Plex 는 구글 폰트에서 받아옵니다.
  APK 를 오프라인으로 열면 시스템 한글 폰트로 대체됩니다. 묶어 넣으려면 한글
  서브셋을 만들어야 하는데 몇 MB 짜리 일입니다
- **리센느** — 구성안대로 브리핑에서 제외. 안내 문구와 Blip 링크만

날씨·결과·알림은 서버(또는 프록시)를 하나 두면 풀립니다. 브라우저에서 직접 호출하면
CORS와 API 키 노출이 걸립니다.
